# Data pipeline (Phase 1)

CartSense uses the **Video Games** category of the
[Amazon Reviews 2023](https://amazon-reviews-2023.github.io/) dataset: the
5-core interaction file (every user and item has at least five reviews) and
the category's product metadata.

All numbers below come from files generated by the pipeline:
[`reports/data_stats.md`](../reports/data_stats.md),
[`reports/clean_report.json`](../reports/clean_report.json) and
[`reports/split_summary.json`](../reports/split_summary.json).

## Running it

```bash
python -m venv .venv
.venv/Scripts/activate            # Windows; use .venv/bin/activate elsewhere
pip install -e "ml[dev]"
python -m cartsense_ml.data.pipeline --config ml/configs/data.yaml
```

Steps can be re-run individually, e.g. `--steps clean stats split`. Downloads
are skipped when the file already exists (`--force-download` overrides).

## Steps

| Step | Module | Input → output |
|---|---|---|
| download | `data/download.py` | source URLs → `data/raw/*.gz` |
| convert | `data/convert.py` | gzip CSV / JSONL → `data/interim/{ratings,products}.parquet` |
| clean | `data/clean.py` | interim Parquet → `data/processed/{interactions,products}.parquet` |
| stats | `data/stats.py` | processed Parquet → `reports/data_stats.{json,md}` |
| split | `data/split.py` | interactions → `data/processed/splits/{train,val,test}.parquet` |

**Streaming.** The 103 MB metadata file (137,269 products for the whole
category) is decompressed and parsed line by line in batches of
`chunk_size` records and written incrementally with a `ParquetWriter`. Only
products present in the 5-core ratings are kept (25,612). Ratings are read with
pyarrow's block-streaming CSV reader. After this step the working set is small
enough to clean in memory.

**Downloads** stream 1 MiB chunks to a `.part` file, check the byte count
against `Content-Length` and rename atomically, so a failed download never
looks complete. TLS is verified against the OS certificate store
(`truststore`), which works behind proxies that inspect HTTPS traffic.

## Cleaning

| Rule | Rows dropped |
|---|---|
| missing user / item / rating / timestamp | 0 |
| rating outside 1–5 | 0 |
| duplicate (user, item) pair, latest kept | 0 |
| product has no title | 1 product, 53 interactions |

Result: **814,533 interactions, 94,762 users, 25,611 products** (density
0.000336). Only 16 users fall below five interactions after cleaning; I keep
them instead of re-applying the 5-core filter, since the effect is negligible.

Product metadata is flattened into typed columns: price parsed from mixed
number/string values (present for 66.9% of products), the MAIN image chosen,
the `Date First Available` detail parsed into a date (95.8%), and the
remaining details stored as JSON.

## Time-based split

Two global cutoffs at the 80th and 90th percentiles of all timestamps:

| Split | Rows | Users | Items | Period (UTC) |
|---|---|---|---|---|
| train | 651,626 | 86,152 | 20,487 | 1999-10-22 → 2019-12-10 |
| val | 81,453 | 29,862 | 11,479 | 2019-12-10 → 2021-07-09 |
| test | 81,454 | 25,013 | 10,995 | 2021-07-09 → 2023-09-02 |

Protocol for later phases: fit on train and evaluate on val for model
selection; refit on train + val and evaluate on test once for the reported
numbers.

**Why global cutoffs instead of leave-last-out per user?** A per-user split puts
some users' 2023 reviews in training while other users are tested on 2015
reviews. The model then learns popularity and co-occurrence patterns from the
"future", which inflates offline metrics. A global cutoff matches how the
system is used: train on everything up to today, recommend for tomorrow.

## What the split tells us about the modelling problem

* **Item cold start is large.** In the test window, 37,640 of 81,454
  interactions (46.2%) involve one of 2,758 products that never appear in
  train + val; in validation it is 22,161 of 81,453 (27.2%). Pure
  collaborative filtering cannot recommend these products, so the
  content-based model and the hybrid ranker have to cover them. CF results will
  be reported with that ceiling in mind.
* **User cold start is moderate.** 3,376 of 25,013 test users (13.5%) have no
  history before the test window; they are served by popularity / category
  signals and reported as a separate slice.
* **Ratings are skewed positive.** 520,043 of 814,533 ratings (63.8%) are
  5 stars, so every review is treated as a positive implicit signal and the
  rating is used as a weight or feature, not a prediction target.
* **The "Legacy Systems" platform holds 11,708 of 25,611 products,** so a
  meaningful share of the catalogue is older-generation games and accessories.
